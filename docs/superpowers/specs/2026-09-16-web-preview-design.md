# 菜猪猪浏览器预览版设计规格

## 目的与边界

浏览器预览版用于让没有 Mac 的用户在 Windows 上验证菜猪猪的产品流程、信息结构和交互。它是原生 iPhone App 的辅助验证工具，不替代 SwiftUI、SwiftData、Share Extension、App Intents、签名或 iOS Simulator 测试。

## 技术方案

- 项目目录为 `WebPreview/`。
- 使用原生 HTML、CSS 与 JavaScript，不安装第三方依赖。
- 通过 `python -m http.server` 在本机提供静态文件。
- 使用单页应用结构；底部标签切换菜谱、导入、采购和库存。
- 菜谱、草稿、采购项和库存事件保存在 `localStorage`。
- 用户图片以 Blob 保存在 IndexedDB；业务记录只保存图片键，不保存超长 data URL。
- 提供可安装 PWA 所需的 manifest、service worker 与离线缓存。

## 视觉与交互

界面采用温暖的家庭厨房气质，以番茄红、奶油白、深棕和少量叶绿色为主。移动宽度下呈现接近 iPhone 的底部标签布局；桌面宽度下显示居中的应用画布和辅助信息，但不转变为企业后台式侧边栏。

主要流程：

1. 菜谱：首页展示真实示例数据，可新建、查看、编辑、删除；字段覆盖名称、简介、食材、步骤、份量、耗时、图片、标签和来源。
2. 导入：支持链接、纯文案以及单张或多张图片；长截图按普通图片处理。所有内容先形成待确认草稿，用户修改并明确确认后才能保存为菜谱。
3. 烹饪：逐步显示当前步骤、关联食材、进度，以及上一项和下一项操作。
4. 采购：可从菜谱生成采购项，也可手动增删、勾选并调整数量。
5. 库存：只能追加入库、消耗和调整事件；当前库存每次由事件汇总，不持久化独立余额。
6. 系统入口模拟器：模拟“从其他 App 分享”和三个快捷指令入口，并显著标注这是流程演示，不是 iOS 系统集成验证。

## 数据与错误处理

- 首次启动写入一份示例菜谱；之后不覆盖用户数据。
- 表单在保存前验证必填名称、正数量和有效步骤。
- 无法读取图片、存储空间不足或数据损坏时显示可恢复错误，不静默丢失已输入文本。
- 提供导出 JSON、导入 JSON和重置演示数据，方便测试和恢复。
- 所有核心流程离线工作；解析 API 仅作为可选演示开关，不是保存菜谱的前置条件。

## 测试与完成标准

- 业务规则拆为无 DOM 的纯 JavaScript 模块，并使用 Node 内置 `node:test` 测试。
- 先观察失败测试，再实现菜谱校验、导入确认、采购合并和库存汇总。
- 使用浏览器自动或人工验证桌面与移动宽度的主流程、键盘操作、焦点、空状态和错误状态。
- 完成时必须能通过一个本地命令启动，并在 Windows 浏览器中完成全部主要流程。

## 非目标

- 不复刻真实 SwiftUI 渲染细节。
- 不声称验证 SwiftData、Share Extension、App Intents、iOS 权限或签名。
- 不加入账号、社交、推荐、视频识别、猪猪养成或强联网依赖。
